# PRD: 雷达-声学融合跟踪与老人居家监控

状态: v0.2 待评审 (2026-09-02)。四项行为决策已由用户确认（跟踪子模式可配置默认纯声音 / 超范围三策略可配 / 无关联声源仍按声音指向 / REST 轮询上报）；舵机确认为 MG90S（180°，现配置不变）；雷达已按 OUT1→GPIO11、RX→GPIO8、TX→GPIO9 接线，Phase 0 可启动。
关联文档: `ArthurReadMe.md`(原始需求) / `CLAUDE_BASE.md`(继承栈权威文档) / `reference/`(雷达手册与协议)

## 1. 概述

在现有声源定位跟踪系统（3DMIC-291 三麦克风 DOA + MG90S 舵机 + REST API，v2.6）基础上，接入 MS60-1211S80M 60GHz 毫米波雷达，实现：

1. **声源-目标关联**：跟踪模式下持续监听声音（现有能力）+ 检测/识别雷达视野内移动或存在的人或物；若声音来自该目标，舵机指向该方向，并把关联结果（目标编号、距离）作为元数据一并输出。
2. **老人居家监控**：基于麦克风阵列（360° 听觉）与雷达（±60° 视觉级感知）的互补能力，让舵机指向跟上场景事件（说话、走动、进入/离开、异常静止），并通过 REST 上报事件。

硬件与安装（当前事实）：
- ESP32-S3 SuperMini + 3DMIC-291（固定安装，`MIC_ARRAY_MOUNTED_ON_SERVO=0`）+ MG90S 舵机直驱 + MS60-1211S80M 雷达
- 雷达放桌面上，位于麦克风阵列**下方 30mm、前方 15mm**（在 2m 距离上方位角影响 <0.5°，忽略；需校准的是雷达 0° 与 12 点方向的偏航角）
- 舵机活动范围 9 点~3 点（±90°，软件限位），超出部分按可配置策略处理（见 FR-7）
- 雷达接线：TX→GPIO9、RX→GPIO8（UART1，**115200 8N1 实测**，见 `tasks/radar-protocol-notes.md`）、OUT1→GPIO11（一期可选）

### 覆盖范围（雷达正对 12 点安装为前提）

```
 9点      10点           12点           2点      3点
  ├─────────└──── 雷达视野 ±60° ────┘─────────┤
  └──────────── 舵机可达 ±90° ────────────────┘
  └──────────────── 麦克风 DOA 360° ──────────┴── (3点~9点后半圈)
```

| 区域 | 麦克风 | 雷达 | 舵机 | 行为 |
|---|---|---|---|---|
| 10点~2点 | ✓ | ✓ | ✓ | 完整融合：关联+指向 |
| 9~10点、2~3点 | ✓ | ✗ | ✓ | 纯声音跟踪（现有行为，标注 unassociated） |
| 3点~9点（后半圈） | ✓ | ✗ | ✗ | 仅事件上报，舵机按超范围策略处理 |

雷达关键规格（产品手册）：水平/俯仰视角 ±60°，运动检测 ≤10m（可配 0~10m），微动/静止人体 ≤8m（可配 0~8m），盲区 0.1m，比相测角（1T2R），建议安装高度 1~1.5m（桌面约 0.75m，偏低但可用，见开放问题）。

## 2. 目标

- G1: 雷达轮询链路稳定：5Hz 轮询 0x30，正常工作状态下校验失败率 < 0.1%，无静默丢回复
- G2: 声源-目标关联：在 10~2 点区域内、目标距离 ≤6m、正常室内噪声下，说话人关联成功率 ≥ 80%
- G3: 关联后舵机指向误差 ≤ ±5°（相对目标真实方位）
- G4: 场景事件从发生到 `/api/events` 可查询，延迟 ≤ 2s
- G5: 新增雷达+融合逻辑 CPU 负载 ≤ 15%（总负载 ≤ 55%）
- G6: 现有纯声音跟踪、REST API、evlog 行为零回归
- G7: 雷达离线（断线/无帧）5s 内检测到，自动降级为纯声音跟踪并上报事件

## 4. 功能需求

- FR-1: 系统必须在 UART1（GPIO8/9）以 921600 8N1 接收雷达主动上报，帧校验失败丢弃并计数，不阻塞其它任务
- FR-2: 系统必须维护雷达主目标状态（Phase 0 实测：本固件仅返回单个聚合目标，经 0x30 轮询获取，见 `tasks/radar-protocol-notes.md`），带时间戳，无目标/超时清除
- FR-3: 雷达角度必须经偏航偏移映射到系统方位角（12 点=0° 顺时针）
- FR-4: 声音 DOA 事件必须尝试与雷达目标关联（门限默认 20°，可配），关联结果作为元数据随状态/事件输出
- FR-5: 跟踪模式必须支持三个子模式（audio_only 默认 / fusion / radar_follow），REST 可切换、重启保持
- FR-6: 有声音但无关联目标时（声源在雷达视野外或非人声源），只要 DOA 可信且在 ±90° 内，仍按声音指向（US-005 的 audio_only/fusion 语义下）
- FR-7: 目标/声源超出 ±90° 时按可配置策略处理：hold（默认）/ clamp / home，并产生超范围事件
- FR-8: 雷达视野外区域（9~10 点、2~3 点、后半圈）的纯声音事件必须标注 unassociated 并上报
- FR-9: /api/status 必须追加雷达与融合字段（向后兼容）
- FR-10: /api/events 必须提供带序号的事件队列，支持 since= 增量拉取，事件镜像到 evlog
- FR-11: 雷达离线判定基于轮询回复超时（连续 3 次 0x30 轮询无回复，≥600ms）→ 离线事件 + 降级纯声音跟踪；恢复后上报恢复事件（Phase 0 结论：主动上报不可用，轮询回复即心跳）
- FR-12: 长静止事件默认关闭、阈值可配（US-009）
- FR-13:（可选）雷达检测距离/灵敏度可经 REST 下发并保存到雷达

## 5. 非目标（本期不做）

- 不做摄像头/图像识别（本机型无摄像头参与闭环）
- 不做跌倒检测（二期评估：运动突停 + 静止微动 + 测高上报的组合启发式）
- 不做呼吸/心率**数值**输出（一期只用微动"存在"状态）
- 不做 MQTT/WebSocket 主动推送（仅 REST 轮询）
- 不做多声源同时定位/分离（沿用现有单声源 DOA 假设）
- 不做音频录制、存储或传输（麦克风仅用于 DOA 计算，保护隐私）
- 不修改麦克风 DOA 算法与校准体系

## 6. 设计考量

- **坐标系**：统一用"钟点方位角"（12 点=0°，顺时针 0~360°）。麦克风 DOA 已是该体系；舵机 target = 方位角 − 180° + home（固定阵列，无前馈）；雷达角经 YAW_OFFSET 换入
- **安装**：雷达与麦克风均固定；30mm 低 / 15mm 前的偏移在 1m 外对方位角影响 <1°，不做立体校正；偏航角必须校准（US-003）
- **检测分区**：以雷达 ±60° 为"关联区"，±90° 为"指向区"，其余为"上报区"（见 §1 表格）
- **降级原则**：雷达是增强件不是依赖件——任何雷达故障不得影响现有声音跟踪
- **隐私**：mmWave 无成像 + 无音频外传，适合居家场景，可对外说明

## 7. 技术考量

- CPU 预算：现有 ~40%（DOA 30% + WiFi/HTTP 10%），雷达解析+融合预计 <15%；雷达任务独立 FreeRTOS task，4KB 栈
- UART1 115200 8N1（Phase 0 实测；AT6010 文档的 921600 默认值不适用本模组）；帧小（<64B），5Hz 轮询负载可忽略
- GPIO11（OUT1）：一期仅预留（可选存在中断触发），不实现
- ~~多目标帧格式~~ Phase 0 已定：主动上报不可用，0x30 轮询单聚合目标（见 `tasks/radar-protocol-notes.md`）
- 模式管理：扩展现有 mode_manager（track/command 基础上加 track 子模式），避免第二套状态机
- 事件队列在内存（32 条），持久化走 evlog（NLS 32 槽）——两者职责：内存队列供实时轮询，evlog 供重启后取证
- 鉴权/限流/CORS 沿用 rest_api.c 现有实现
