# 双 WiFi 槽位故障转移（居家 + 手机热点）

状态: 实施完成，待台架验证（2026-10-14）
决策记录: 不做自动优先级复归 —— 原型阶段回家断电重启即可恢复 .113（开机固定从槽位 0 起连）；轮换参数进 board_config.h；凭据保持 gitignored wifi_creds.h 模式

## 1. 槽位语义

槽位顺序 = 优先级。开机永远从槽位 0 开始；当前槽位重试预算耗尽才轮换到下一个。

| 槽位 | 网络 | IP 模式 | 用途 |
|---|---|---|---|
| 0 | 居家 WiFi（wifi_creds.h WIFI0_*） | 静态 .113（heizai 身份） | 居家部署，外部调用方固定地址 |
| 1 | 手机热点"夜空中的星米"（WIFI1_*） | DHCP | 外出，仅 MQTT 上报（broker 为公网域名，无固定 IP 需求） |

## 2. 状态机（wifi.c）

- 断线后同槽位快速重试，预算 `WIFI_SLOT_RETRY_MAX`（默认 3）次——覆盖瞬时掉线（路由器重启抖动），不掉槽。
- 预算耗尽 → 轮换下一槽位：`apply_ip_mode()` + `set_sta_config()`（在断开窗口内执行，netif 重配的安全时机），然后 `WIFI_SLOT_SWITCH_DELAY_MS`（默认 5s）单次软件定时器到点再 `esp_wifi_connect()`。
- 连上即粘住（GOT_IP 只清重试计数，不动槽位）；断线恢复轮换。
- 双网皆空时无限轮换，完整周期约 30s，不轰击射频。
- 顺带修复: 旧代码在事件回调里 `vTaskDelay(10s)` 阻塞默认事件循环（期间 MQTT 等所有事件停摆），已改为软件定时器，回调零阻塞。

## 3. IP 模式规则

`apply_ip_mode(slot)`: 静态槽位 = `dhcpc_stop` + `set_ip_info` + DNS；DHCP 槽位 = `dhcpc_start`。

**关键约束**: `ESP_ERR_ESP_NETIF_DHCP_ALREADY_STOPPED/STARTED` 属正常返回（如开机预配置、重复进入同模式槽位），代码只记日志、**绝不能 `ESP_ERROR_CHECK`**，否则直接 panic 重启。

## 4. 参数（board_config.h）

| 参数 | 默认 | 含义 | 调整建议 |
|---|---|---|---|
| `WIFI_SLOT_RETRY_MAX` | 3 | 同槽位断线快速重试次数 | 路由器经常长时间重启的环境可加大，代价是轮换变慢 |
| `WIFI_SLOT_SWITCH_DELAY_MS` | 5000 | 切槽位后到发起连接的停顿 | 调小则双网皆空时轮换更快，但射频扫描更频繁 |

## 5. 恢复策略（为什么没有自动复归）

已知场景: 在家时路由器重启期间热点恰好开着 → 设备可能粘在热点，.113 失效。

决策: 不实现扫描复归（约 +25 行）。开机固定从槽位 0 起连保证了**断电重启即回家**。原型阶段可接受；若未来需要无人值守自动回 .113，再加"非 0 槽位连接时定期静默扫描槽位 0 SSID"逻辑。

## 6. 前置条件与坑

- **手机热点必须 2.4GHz**: ESP32-S3 不支持 5GHz。小米/安卓在热点设置选 2.4GHz 频段；iPhone 开"最大兼容性"。症状: reason=201 NO_AP_FOUND 持续出现。
- 中文 SSID 无碍: UTF-8 字节串，"夜空中的星米" 15 字节 < 32 上限。
- 热点子网与家不同（安卓常见 192.168.43.x 或随机、iPhone 固定 172.20.10.x/28）——DHCP 槽位天然规避。**实测 2026-10-14**: 小米 MIUI 热点"夜空中的星米"随机分到 10.117.140.0/24（每次开热点可能变），脖子 DHCP 拿到 .235；热点网内 mDNS 可用（esp32-mic-58e4.local），态势页/REST 从热点内设备访问正常。**DHCP 租约实测**: 有效期 1h、T1 续租 30min——连接期间每 30min 静默续租、IP 不变；跨热点会话（关开热点）网段和 IP 才会变，热点网内访问统一走 mDNS 名。
- reason code 速查（wifi.c reason_str 解码会打进日志）:

| code | 含义 | 排查方向 |
|---|---|---|
| 201 | NO_AP_FOUND | 频段错(5GHz热点)/信号范围外/SSID 拼错 |
| 202 / 15 | AUTH_FAIL / 4WAY_HANDSHAKE_TIMEOUT | 密码错 |
| 200 | BEACON_TIMEOUT | 连接后信号丢失 |
| 203 / 204 | ASSOC_FAIL / HANDSHAKE_TIMEOUT | 关联被拒（MAC 过滤等） |
